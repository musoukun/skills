# 仕組みの見せ方の決まり（動き・時間・つなぎ）

例題（APCBC）を作り直したときに、ユーザーから指摘された失敗をもとにした決まり。題材が変わっても同じように使う。

## 解説の運び（いちばん大事）
仕組みの解説は「仕組みが働く瞬間に何が起きているか」を見せること。だから次の順で作る。

1. **現実の状況で動かす。** 実際に起こりうる想定（例: 水平に飛んできた砲弾が、戦車の上段の傾斜装甲に当たる）を基準にし、物理法則をゆがめない。
2. **仕組みが働く瞬間ごとに時間を止める。**（触れた瞬間、つぶれた瞬間、届いた瞬間…）
3. **止めたまま説明する。** カメラだけが動いて寄る・回り込む。名札で「何が起きているか」を示す。
4. **再開して、次の瞬間へ。** 再開のきっかけは次の字幕。

```js
// 止める瞬間（世界の時刻）と、再開する字幕を並べるだけ
const W = timeWarp([{ at: tHit + 0.12, until: ctx.cue('impact', 1) }, { at: tBite + 0.03, until: ctx.cue('impact', 2) }]);
update(t) { const w = W(t); /* 物・火花・炎は w で、カメラと名札は t で動かす */ }
```

## 失敗と決まり

| 失敗したこと | なぜ悪いか | 決まり |
|---|---|---|
| 着弾の位置を目分量で決め、車体の角に当たっていた | 「斜めの装甲だから弾かれる/食い込む」という説明の前提が絵で成り立たない | **当たる場所は形から求める。** `findSlope`（法線の向きと平らさで斜面を探す）・`surfaceHit`（レイで点と法線）。説明が「斜めの面」なら、平らな斜面の真ん中に当てる |
| 生成モデルを「180°回せば前を向く」と決め打ちした | 画像から作ったモデルは元画像のカメラの向き（斜め 3/4）のまま。実際は 45° ずれていた | **向きは頂点から求める。** `headingYaw`（上から見た主軸＋長く突き出た側が前）→ 当てる面の法線の横成分が 0 になるよう微調整 → still で確かめる |
| 本物の戦車があるのに、的はただの斜めの板だった | 参考動画は実物の傾斜装甲に当てている。板は「何の話か」が伝わらない | **代用の板は、本物が無いときだけ。** 本物のモデルの、説明に出てくる部分（上段の傾斜装甲・側面の斜め）を的にする |
| 跳弾で宙返りさせた／鏡のように大きく跳ね返した | 現実の跳弾は面に沿って滑って抜ける（⤴）。回転は飾りで、物理をゆがめる | **跳ね返りは `glance`**（面に沿う成分を残し、面から少し離れる）。**向きは速度の向きになめらかに合わせるだけ**。回すのは自分の軸まわり（ライフリング）だけ |
| 着弾のあとカットを切り、スタジオで別の砲弾を見せた | 参考は「当たった瞬間に時間が止まり、そのまま寄って先端を見せる」1カット。別の物に替わると、同じ砲弾の話に見えない | **同じ物・同じ瞬間を続けて見せる。** 字幕の区切りでシーン id が変わっても、1つの組み立て関数を共有し、動画全体の時刻 T と `camKeys` で動かす（例題の `strikeAndFreeze`） |
| 飛んでくる砲弾が尖っていて、あとで「実は丸い」と言った | 絵と説明が食い違う | **主役の物は最初から本物の形で出す。** 遠目には分からなくても、止めて寄れば分かる |
| 止めた瞬間に、物がもう跳ね返る向きに傾いていた | 止めるのは「触れた瞬間」。向きの変化は再開後 | 止める時刻（`at`）は変化が始まる直前。向きの補間は止める時刻より後に始める |
| 先端を見せるカメラが後ろ寄りで、胴体しか映らなかった | 見せたい部分（先端と面の境目）が画面にない | 見せたい部分が**輪郭として**見える向き（真横など）からカメラを置く。still で必ず確かめる |
| 名札が画面の端で切れた | 縦長は横が狭い | ランタイムが名札を画面の内側に押し込む。それでも重なる場合は offset を内側へ |

## 作る前にやること（参考動画があるとき）
- 1秒1枚のシートでは「何が起きる瞬間か」が粗い。**仕組みが働く前後（着弾・跳弾・つぶれる所）は 1秒4枚で並べて見る**:
  `ffmpeg -ss 3 -t 6 -i ref.mp4 -vf "fps=4,scale=200:-1,tile=8x3" -frames:v 1 strip.jpg`
- 字幕ごとに **ビート表**を書いてから作る。列は「字幕 / 何が起きるか（物理） / どこに当たるか / 時間（普通・スロー・停止） / カメラ / 次へのつなぎ（切る・続ける）」。
- 作ったら、参考の同じビートのコマと**並べて**見比べる（`hstack`）。「動いているか」ではなく「同じことを説明できているか」を見る。

## 重い処理の注意
- 数十万三角形のモデルへのレイは重い（斜面探しで数千本）。結果は**モデルに対して一度だけ**求め、置いた場所に変換して使い回す（例題の `placeTank` の `slopeCache`）。全カットでやり直すと、読み込みが数分かかる。
