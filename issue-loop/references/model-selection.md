# モデルの使い分け（コストを抑える）

役割は3段階に分ける。

- **会話している本体**：理解・A/B 判定・設計・plan 作成と承認・人間との対話・合格判定
- **強いモデルのサブエージェント**（Claude Code なら `model: "opus"`）：plan 承認後の実装・調査・検証
- **軽いモデルのサブエージェント**（`model: "sonnet"`）：要約・決まったコマンド・機械的な作業

| フェーズ | 担当 | 理由 |
|---|---|---|
| Pre-flight の3つの質問 | 本体 | 人間との対話 |
| Step 1: 候補取得と表づくり | 軽いモデル | JSON を絞って表にするだけ |
| Step 2: 各候補を軽く読む | 軽いモデル | 要約 |
| Step 3: 3件を選ぶ | 本体 | 何を選ぶかの判断 |
| 4-1: 理解（リンク先・画像を読む） | 本体 | A/B 判定と plan の根拠になる。自分の目で読む |
| 4-2〜4-3.6: 判定・設計・質問・plan | 本体 | 設計の判断が最重要 |
| 4-4: ブランチ作成 | 軽いモデル | 決まった操作 |
| 4-5: Before キャプチャ | 強いモデル | 事故を避ける判断が要る |
| 4-6a〜c: 実装・チェック・After | 強いモデル | plan＋対象ファイルだけ渡す。本体は指揮だけ |
| 4-6d: ゴール達成の自己レビュー | 本体 | 合格判定は重要 |
| 4-7〜4-10: 証拠コメント・assignee・push・PR | 軽いモデル | 雛形に当てはめる・決まった操作 |
| 4-11: レビュー指摘対応 | 判断は本体、修正は強いモデル | 直すか返すかの判断は本体 |
| Step 5: 終了報告 | 本体 | 人間への報告 |
