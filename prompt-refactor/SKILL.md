# 意訳のすすめ

このスキルの目的は、AI への指示を、人が読んで直しやすい形にしながら、AI のふるまいを変えないことです。
条件を 1 行ずつ足してきた指示は、似た条件が散らばり、ぶつかる決まりも混ざって、AI が全体の目的をつかみにくくなります。
目的ごとの段落にまとめ直すと、書いていない場面でも、AI が目的から判断できるようになります。
この形にした根拠は `references/文献.md`、ここまでに外れたことは `references/lessons.md` にあります。

文中の例は、架空の家電メーカー「サンプル電機」のサポートチャットです。
自分の指示に合わせて読み替えてください。

## 書き直すときの指示

指示を書き直すときは、次の 8 つを守ります。
別の AI に書き直しを頼むときも、この 8 行をそのまま渡します。

```
指示を、見出し 1 つずつ、汎化して意訳して書き直して。
構成と長さはほぼ保って。
消してよいのは、言葉だけ変えて言い直した重なりと、ぶつかる決まりだけにして。
間違えたときの害が大きい決まりは、決まりのまま残して。
書き直す前に、ぶつかる決まりの組を書き出して、どちらを取るかを聞いて。
段落の 1 文目には、その段落の手順ではなく、守らせたい目的を書いて。
1 文は 156 文字以内にして。
文の終わりは「。」で区切って。
```

8 つにはそれぞれ、外れた経験があります。
「短く」とだけ頼むと、決まった言い回しや確かめる順番まで消え、テストで落ちました。
全部を一度に書き直すと、ふるまいが変わったときに、どの見出しが原因かを見分けられませんでした。
段落の 1 文目を手順にすると、書いていない場面で、AI が何を守ればよいかを判断できませんでした。
156 文字を段落の上限と読まれないよう、「1 文は」と書いています。

## 書き直しの手順

書き直しの前に、指示を決まりとそのディテールまで、全部チェックリストの項目に分けます。
ディテールとは、順番、決まった言い回し、数の上限、確かめる項目、例外、例のことです。
項目ごとに、元の場所と元の文、間違えたときの害の大きさ（大・小）、ぶつかる項目を書きます。
利用者の安全、お金、権限、相談先、守る順番に関わる項目は、害が「大」です。

次に、ぶつかる組を人に見せ、どちらを取るかを決めてもらいます。
人の答えが出るまでは、ぶつかる組を両方とも元の文のまま残します。
指示に書かれていない条件は、書き直しで足しません。
足したほうがよい条件は、「足す候補」として人に見せます。

書き直したら、チェックリストの項目を 1 つずつ、書き直した指示と照らし合わせます。
どの段落のどの文に入ったかを書けない項目は、落ちた項目なので、戻します。
最後に、書き直す前と後の文字数と、戻した項目の数と、人に聞くぶつかる組を伝えます。

書き直した指示は、使う前に、書き直す前と同じ問題で動かして比べます。
見出しを 1 つ書き直すたびに、少ない数の問題を流します。
その問題が書き直す前と同じくらい通るまで、次の見出しにも、全部の問題にも広げません。
AI の答えは回ごとにぶれるので、同じ問題を何回か流し、同じ問題どうしで比べます。

## 指示を縮める手順

指示を縮める目的は、AI に渡す量を減らしながら、AI のふるまいを変えないことです。
縮めてよいかは、文の長さではなく、文の役目で決まります。
上の 8 つの指示は「構成と長さはほぼ保つ」書き直しで、ここは長さを減らす書き直しです。
詳しいやり方と例は `references/compress.md` にあります。縮める前に読みます。

1. 文を役目で分けます。役目は、操作の中身、共通の指示の言い直し、伝える中身の指示、会話の流れを決める文、の 4 つです。
2. 書いていないのに動いている判断を探し、先に文にします。「最初に聞くこと」の答えを、どこで使うかが書いてあるかを確かめます。
3. 操作の中身は、資料のどの部分かを指す形にします。このとき、この返事でどこまで済ませるか、知らせるのかやってもらうのか、何を使って始めるか、の 3 つを変えません。
4. 共通の指示の言い直しは、共通の指示の文を引用できた組だけ消します。
5. 伝える中身の指示は、縮め方を人に選んでもらいます。伝えること自体は消しません。
6. 会話の流れを決める文は消しません。最初に聞くこと、分かれ道、窓口へつなぐ所、操作の種類の札と例外、相談先です。
7. 縮める前に毎回通った採点基準で、縮めた指示がどれだけ通るかを確かめます。

手順 5 では、書き直す前に、次の 2 つから選んでもらいます。

| 選び方 | 書き方の例 | 気をつけること |
|---|---|---|
| A. 資料を指す | 「資料にある、フィルターが詰まると何が起きるかの説明を伝える。」 | よく縮む。小さいモデルや弱いモデルは、指した先をうまく参照せず、説明を言わなくなることがある |
| B. 中身を短く残す | 「フィルターが詰まると吸う力が落ちることを伝える。」 | 縮む量は小さい。小さいモデルや弱いモデルでも言う。資料が変わったら指示も直す |

使うモデルが小さいか、資料が毎回は AI に渡らない作りなら、B を勧めます。
安全、お金、権限に関わる注意は、どのモデルでも B にします。

1 回の書き直しで縮めるのは、1 種類の文だけにします。
ある案件の手順書では、手順 3 と 4 で 72% まで、手順 5 の A も使うと 64% まで縮みました。
会話の流れを決める文まで消した 48% の版は、ふるまいが変わりました。

## 重なりの見分け方

重なりを消す目的は、同じ決まりを 1 か所で直せるようにすることです。
ただ、共通の指示と同じことを言う文でも、消すと AI が共通の決まりを目の前の場面に当てはめられなくなる文があります。
消してよいかは、「この文が無くても、AI は共通の決まりをこの場面に当てはめられるか」で決めます。

下の例の共通の決まりは、「取り返しのつかない操作を案内する前に、利用者に確かめる」です。

| 文の種類 | 例 | 扱い |
|---|---|---|
| 具体的な物の名前を、共通の決まりの種類に結び付ける文 | 「アプリの『本体を初期化』のボタンを押す操作は、取り返しのつかない操作」 | 残す |
| その操作に、共通の決まりの例外が当たると書く文 | 「この操作は電源を入れ直せば戻るので、確かめなくてよい」 | 残す |
| 言うタイミングや、言う場所を決める文 | 「原因ではないことを、結果を聞くこの返事で伝える」 | 残す |
| 手順の段の中で、その段で言うことを書いた文 | 「フィルターが古ければ交換する、という条件付きの手順として示す」 | 残す |
| 共通の決まりを、言葉だけ変えて言い直した文 | 「初期化の前には、利用者に確かめる」 | 消してよい |

共通の指示は「取り返しのつかない操作」のように、種類の名前でしか書けません。
どの画面や操作がその種類に当たるかは、話題ごとの指示にしか書けないので、結び付ける文は残します。
言うことを事実の文に書き換えると、AI は言わなくなります。

消すときは、種類ごとに少しずつ消します。
1 種類を消したら、その文があった話題の問題を数問ずつ何回か流し、消す前と同じくらい通るかを確かめます。
落ちたら、その種類の文は残し、なぜ AI に要ったのかを会話の全文で確かめます。

## 食い違いの見つけ方

食い違いは、同じ場面で、片方に従うともう片方に従えない 2 つの文のことです。
食い違いは、指示が守られなくなるいちばん大きな原因です。
両方が当てはまる場面を具体的に言えるものだけを、食い違いとして挙げます。

食い違いは、どの場面にも当てはまる決まりと、その例外が離れて書かれた所に多く出ます。
例外が別のファイルや見出しに、例外だと書かれずに置かれていると、AI はどちらに従えばよいか迷います。
例外は、元の決まりと同じ段落に置くか、元の決まりに「場面ごとに違う」と書きます。

見つけたら、場面と、ぶつかる 2 つの文をそのまま引用して並べます。
どちらを取るかは、応対の決まりそのものなので、人が決めます。

指示のファイルが多いときは、観点ごとに別の AI に読ませます。
観点は、食い違い、重なり、置き場所の違い、書き方、フローの抜けの 5 つです。
役に渡すのは、観点の名前と、`references/review.md` と、資料をまとめたファイルだけにします。
こちらの見立てを渡すと、役はそれを確かめるだけになるので、渡しません。

資料をまとめるのと、引用が資料に本当にあるかを確かめるのは、`scripts/review_prompts.py` でします。
Python の標準のライブラリだけで動きます。

1. AI が読む資料の一覧を、JSON で書きます（初めの 1 回だけ）。

   ```json
   {
     "sources": [
       {"name": "persona.md", "path": "prompts/persona.md", "when": "会話の最初に受け取る"},
       {"name": "playbook.md", "path": "prompts/playbook.md", "when": "会話の最初に受け取る"},
       {"name": "topics.yaml", "path": "prompts/topics.yaml", "when": "その話題の資料が検索で当たったときだけ受け取る"},
       {"name": "AI が呼ぶ処理", "path": "prompts/tools.md", "when": "処理を選ぶときに読む"}
     ],
     "placement": [
       {"source": "persona.md", "write": "どの場面でも同じ、話し方と返事の書き方", "dont": "場面で変わる話し方"},
       {"source": "topics.yaml", "write": "その話題にだけ当てはまること", "dont": "どの話題にも当てはまる進め方"}
     ]
   }
   ```

   `placement` は、ファイルごとに何を書き、何を書かないかの決まりです。
   置き場所の違いを探す役が使います。
   無ければ、置き場所の違いの観点は飛ばします。

2. 資料を 1 つにまとめます。

   ```bash
   python3 <このスキルのフォルダ>/scripts/review_prompts.py collect --manifest prompt-sources.json
   ```

   `.prompt-review/sources.md` に、資料と置き場所の決まりが入ります。
   前の回の結果（`findings-*.json`）は消えます。

3. 5 つの観点ごとに 1 つずつ、レビューする役を並べて立てます。
   役には次のとおりに頼みます。

   ```
   あなたは、AI への指示を読み比べるレビュー役です。受け持つ観点は「<観点>」です。
   1. <このスキルのフォルダ>/references/review.md を読む。
   2. .prompt-review/sources.md を最初から最後まで読む。
   3. 「<観点>」に当たるものを全部、review.md の形の JSON の配列で .prompt-review/findings-<観点>.json に書く。
   ほかのファイルは書き換えない。返事には、書いた件数だけを書く。
   ```

4. 5 つとも終わったら、引用を確かめます。

   ```bash
   python3 <このスキルのフォルダ>/scripts/review_prompts.py check
   ```

   資料に無い引用は外れ、引用が足りなくなったものは「外したもの」に移ります。
   結果は `.prompt-review/review.md` に出ます。
   役が挙げたものも AI の見立てなので、本当に食い違うかは、人が全文を読んで決めます。

## テストで外れた会話の直し方

外れた会話を直す目的は、採点に通すことではなく、お手本の会話に近づけることです。
外れるたびに、その場面の文を 1 行足すと、同じ種類の応対が散らばり、ぶつかる決まりが増えます。

最初に、外れた会話をお手本の会話と左右に並べ、誰の外れかを決めます。
ボットがお手本と違う方向に進んだなら、ボットの外れです。
ボットがお手本と同じことを言っているのに落ちたなら、採点の基準か採点役の外れです。
利用者役の AI がお手本と違うことを言って会話がそれたなら、利用者役の外れです。
ボットの指示を直すのは、ボットの外れのときだけです。

ボットの外れなら、会話の記録で、その返事の前に何を検索し、何を読んでいたかを見ます。
正しい資料を読んでいなければ、指示ではなく、検索か資料を直します。
正しい資料を読んだのに違うことを言ったなら、何を見分けられなかったかを 1 文で言い直します。

そのうえで、直す場所を決めます。
決まりのとおりに動いて外れたなら、決まりがお手本と逆なので、逆を言う文を直します。
どの話題にも出る外れなら、共通の指示の文を直します。
その話題だけの外れなら、話題ごとの手順書を直します。
同じ型の応対が、いくつもの話題でばらばらに書かれていたら、1 つの流れとしてまとめ、散らばった文を消します。

文を直すときも、上の 8 つの指示で書きます。
直したら、外れた問題に加えて、前に通っていた問題も流します。
前に通っていた問題が落ちたら、その直しは特定の会話に合わせたものだったと見て、直し方を考え直します。

決まりが守られないときに、AI の考える量やモデルを上げて直そうとはしません。
上げても直らないことが多く、返事のすべてが遅くなります。
どの指示のどこが守られない原因かを考えて、指示を直します。
