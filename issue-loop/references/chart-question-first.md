# グラフ・表を作る前に「何を見たいのか」を言葉にする

issue-loop の 4-3.6（plan を書く）で、グラフ・表を作るときに読む。

## よくある失敗

「分布だけだとどう見たらいいか分からない」というフィードバックに対して、日ごとの売上を**足し上げた累積グラフ**を作ってしまう。累積グラフは右へ行くほど必ず増えるので、「どの曜日に売れているか」という本当に知りたいことが読めない。

原因は、**この図で答えたい問いを、実装前に一度も言葉にしていない**こと。起票者の言葉を見せ方の指示として受け取り、その裏の問いに戻していない。

## 決まり

**グラフ・表を作る前に、次の 3 つを 1 行ずつ plan に書く。**

1. **問い**: この図で答える問いは何か（例:「どの曜日に売れるか」）
2. **読み取り方**: 読み手は図のどこを見て答えを得るか（例:「棒の高さを曜日どうしで比べる」）
3. **却下した形式と理由**: なぜ他の形にしないか（例:「累積は必ず増えるので売れる曜日が読めない」）

3 つが書けないときは、実装せずに起票者へ問いを確認する。

## 形の選び方の目安

| 答えたい問い | 使う形 | 使ってはいけない形 |
| --- | --- | --- |
| いつ・どこが多いか（量の比較） | その時点の実数の棒 | 累積（必ず増えるので比べられない） |
| 全体に占める割合 | 100% 積み上げ・円 | 実数の積み上げ（母数の違いが混ざる） |
| 時間に沿った増減 | 折れ線（実数） | 累積 |
| 合計に到達する過程・進み具合 | 累積 | — （累積が正しいのはここだけ） |

## 追加する前のチェック（3 点）

1. **同じ意味の図がすでに無いか**。読んだ後に残る結論が同じなら重複なので、片方を消す
2. **読み取れることを、主語と比較対象のある 1 文で言えるか**。「多い / 少ない」で終わる図は比べる軸が足りていない
3. **同じ画面の図どうしで、軸の単位と表記が揃っているか**。時間の刻み・数の単位・同じ意味の系列の色を揃える。データの都合で揃わないときは理由を書いて起票者に確認する

自己レビュー（4-6d）では、最初に「この図は plan に書いた問いに答えているか」を見る。見た目が整っていても、問いに答えていなければ作り直す。
