# 指示の書き直しについての文献

このスキルの手順が、提供元の手引きや研究とどう合うかを、書き直す前に確かめるための一覧です。
別の AI に調べさせ、実際に開いて読んだ資料だけを載せています。
論文の多くは、要旨のページだけを読んだものです。

## 分かったこと

提供元の手引きは、決まりを並べるより、目的や理由を書くよう勧めています。
理由を書くと、モデルは書いていない場面にも当てはめます。
ただし、間違えたときの害が大きい所は、決まりで書くほうがよいとされています。

指示の数が増えるほど、守られにくくなります。
守られなくなる主な原因は、指示どうしの食い違いだという研究があります。
食い違いを消すと性能が上がった例も、提供元の手引きにあります。

書き直しでふるまいを保つ方法は、どの道具も、評価用の問題を流した点数です。
書き直す前の文と照らし合わせて保つ手法は、見つかりませんでした。
同じ指示でも回ごとに合否が割れるので、同じ問題を何回か流し、同じ問題どうしの差で比べます。

## 提供元の手引き

| [OpenAI GPT-4.1 Prompting Guide](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide) | 指示を文字どおりに受け取る。食い違うと、後ろに書いた方に従いやすい。直すときは、まずはっきりした 1 文を書き、次に食い違う指示が無いかを見る |
| [OpenAI GPT-5 prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5_prompting_guide) | 食い違う指示は、折り合いを付けるのに考える量を使わせる。食い違いを消したら性能が大きく上がった例がある |
| [OpenAI GPT-5.1 prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5-1_prompting_guide) | 直しは 2 回に分ける。1 回目で失敗の種類と原因の行を特定し、2 回目で小さな直しを出す。構成と長さをほぼ保つ条件を付ける |
| [OpenAI GPT-5.2 Prompting Guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5-2_prompting_guide) | 1 回に 1 つだけ変え、そのたびに評価を流し直す |
| [Anthropic Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) | 指示の理由を書くと、書いていない場面にも当てはめる。強い言い方は新しいモデルには効きすぎる |
| [Anthropic Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 条件分岐の直書きも、ぼんやりした方針も、どちらも失敗しやすい。例外を並べるより、代表的な例を少し置く |
| [Anthropic Claude's constitution](https://www.anthropic.com/constitution) | 決まりは予測しやすく確かめやすい。間違えたときの害が大きい所は、決まりで書くほうがよい |

## 研究と実務

| 資料 | 書いてあること |
|---|---|
| [CDCT](https://arxiv.org/abs/2512.17920) | 指示を中くらいの長さに縮めたとき、制約を守る率がいちばん悪かった |
| [IFScale](https://arxiv.org/abs/2507.11538) | 指示を 500 個まで増やすと、いちばん良いモデルでも正解率は約 68% だった |
| [Instruction Stacking Collapse](https://neurips.cc/virtual/2026/160496) | 指示を重ねると守る率が落ち、主な原因は指示の組の食い違いだった。強いモデルは書き直してもほぼ変わらなかった |
| [What Prompts Don't Say](https://arxiv.org/abs/2505.13360) | 書いていない要求に頼るプロンプトは崩れやすい。要求を全部書いても、食い違いで解決しない |
| [A Taxonomy of Prompt Defects](https://arxiv.org/html/2509.14404v1) | 理由の記録が無いと、後の人が失敗を防いでいる言い回しを消してしまう |
| [GEPA](https://arxiv.org/abs/2507.19457) | 直しに使う問題と、選ぶための問題を分ける。分けないと、直しに使った問題に合わせすぎる |
| [Anthropic A statistical approach to model evaluations](https://www.anthropic.com/research/statistical-approach-to-model-evals) | 2 つを比べるときは、同じ問題どうしの差で比べる。要る問題の数を先に計算する |
| [Anthropic Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | エージェントは同じ問題でも回によって合否が変わる。お客様に向けるものには、k 回全部成功する率が合う |
| [τ-bench](https://arxiv.org/abs/2406.12045) | 8 回全部成功する率は 25% 未満だった |
