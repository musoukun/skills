# push と PR の決まり（issue-loop Step 4-9 / 4-10）

## push

1. リポジトリのルートで、設定のチェックコマンド（lint・型チェック・テストなど）を流す
2. 落ちたら push しない。直してから流し直す
3. 通ったら push する。初回は `git push -u origin HEAD:<ブランチ名>` と行き先を明示する

## PR

- **向き先**: base ブランチ（既定は `main`）
- **タイトル**: 短い日本語。issue 番号は入れない（例:「ログイン後のリダイレクトを修正」）
- **本文の 1 行目**: `Closes #<issue番号>`。issue が PR につながり、マージで issue が閉じる。複数あれば 1 行に 1 つずつ並べる
- **レビュアー**: 設定のレビュアーを付ける

```bash
gh pr create --base main --reviewer <レビュアー> \
  --title "<日本語のタイトル>" --body "$(cat <<'EOF'
Closes #<issue番号>

## 概要
...
EOF
)"
```

- **マージ**: レビュアーがマージする。自分ではマージしない（頼まれたときだけ）

注意: `Closes #N` で issue が自動で閉じるのは、PR の向き先がリポジトリのデフォルトブランチのときだけ。向き先が別のブランチなら、マージ後に issue を手で閉じる。
