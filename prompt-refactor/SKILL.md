# プロンプトのリファクタ

このスキルの目的は、AI への指示を、AI のふるまいを変えずに、重なりの少ない短い形に整えることです。
プログラムのリファクタリングと同じで、情報を 1 つも減らさず、重なりと言い回しだけを整えます。
ここまでに試して外れたことは `references/lessons.md`、提供元の手引きや研究との照らし合わせは `references/文献.md` にあります。

文中の例は、架空の家電メーカー「サンプル電機」のサポートチャットです。
自分の指示に合わせて読み替えてください。

## やること

既定でやるのは、次の 4 つです。

1. 共通の指示にある決まりを、話題ごとの指示で言い直した文を消す。
2. 言い回しの繰り返しを詰める。
3. 同じ話題の中で 2 回書いてある文を、1 か所にする。
4. 書いていないのに動いている判断を見つけて、人に見せる。

4 つだけでは、ほとんど縮まないことがあります。
ある案件の手順書では、4 つで 2% ほどしか縮みませんでした。
もっと縮めたいときは、人に聞いてから、次の 5 と 6 から選んで足します。
5 は、試験で確かめることを条件にします。
6 は、変わる量が大きいので、案を 1 つずつ人に見せ、OK が出たものだけ直します。

5. 操作の押す順を、元の文に書いてある資料の名前と番号を指す形にする。
6. 条件を if-else のように並べた指示を汎化して、AI に目指してほしい姿を書いた「〜していること」の 1 文に意訳する。

詳しいやり方と例は `references/refactor.md` にあります。書き直す前に読みます。

## しないこと

次のことは、しません。
ある案件の試験で、どれもふるまいが変わりました。

| しないこと | 例 | 試験で起きたこと |
|---|---|---|
| 元の文に無い指す先を作って、操作の押す順を消す | 番号だけ書いてあった所に資料の名前を足して指した。指す先が書いていなかった所に、別の話題の資料を指した | 指した手順を、ボットが案内しなくなった |
| 説明や注意を、「資料にある〜を伝える」に替える | 「フィルターが詰まると吸う力が落ちる」を「資料にある説明を伝える」にする | 預けた説明を、ボットが言わなくなった |
| 人に見せずに、何か所かの文を共通する 1 文に言い換える（汎化） | 「詰まっていなかった、または掃除しても直らない：次へ」を「直らなければ次へ」にする | まとめた文から抜けた場合で、ボットが次へ進まなかった |
| 会話の流れを決める文を消す | 最初に聞くこと、分かれ道、窓口へつなぐ所、操作の種類の札と例外、相談先 | 聞かなくてよいことを聞いた。窓口へつながなかった |

利用者にそのまま見せる中身（操作の手順、説明、注意、警告の文、相談先、URL）と、決まった言い回し、固有名詞が主語の例外の文は、1 文字も変えません。

## 書き直しの手順

1. 指示のファイルを全部、最初から最後まで読む。書き直すファイルだけでなく、一緒に AI に渡る共通の指示も読む。
2. `references/refactor.md` のやり方で、4 つを順にする。人が 5 や 6 を選んだときは、それもする。6 は、直す前に案の一覧を人に見せ、OK が出たものだけ直す。
3. 書いていないのに動いている判断と、ぶつかる決まりの組は、書き直さずに元の文のまま残し、人に聞く一覧に書く。
4. 書き直す前と後の文字数、手順のそれぞれで消した数、人に聞く一覧を伝える。
5. 書き直す前の指示で毎回合格する問題を先に決め、書き直した指示でも毎回合格するかを確かめる。AI の答えも採点も回ごとにぶれるので、同じ問題を 2 回以上流し、同じ問題どうしで比べる。合格しなくなった問題は、会話を書き直す前と並べ、どの書き直しで何が言えなくなったかを探して、その文を元に戻す。

採点基準ごとの合否を数えて比べると、変わったことが埋もれます。
ある案件では、採点基準ごとに数えて 99% 通った版が、問題ごとに見ると、毎回合格する問題の半分しか守れていませんでした。
比べるのは、問題ごとの合否と、会話の中身にします。

## 食い違いの見つけ方

食い違いは、同じ場面で、片方に従うともう片方に従えない 2 つの文のことです。
食い違いは、指示が守られなくなるいちばん大きな原因です。
両方が当てはまる場面を具体的に言えるものだけを、食い違いとして挙げます。

食い違いは、どの場面にも当てはまる決まりと、その例外が離れて書かれた所に多く出ます。
例外が別のファイルや見出しに、例外だと書かれずに置かれていると、AI はどちらに従えばよいか迷います。
例外は、元の決まりと同じ段落に置くか、元の決まりに「場面ごとに違う」と書きます。

見つけたら、場面と、ぶつかる 2 つの文をそのまま引用して並べます。
どちらを取るかは、応対の決まりそのものなので、人が決めます。

指示のファイルが多いときは、観点ごとに別の AI に読ませます。
観点は、食い違い、重なり、置き場所の違い、書き方、フローの抜けの 5 つです。
役に渡すのは、観点の名前と、`references/review.md` と、資料をまとめたファイルだけにします。
こちらの見立てを渡すと、役はそれを確かめるだけになるので、渡しません。

資料をまとめるのと、引用が資料に本当にあるかを確かめるのは、`scripts/review_prompts.py` でします。
Python の標準のライブラリだけで動きます。

1. AI が読む資料の一覧を、JSON で書きます（初めの 1 回だけ）。

   ```json
   {
     "sources": [
       {"name": "persona.md", "path": "prompts/persona.md", "when": "会話の最初に受け取る"},
       {"name": "playbook.md", "path": "prompts/playbook.md", "when": "会話の最初に受け取る"},
       {"name": "topics.yaml", "path": "prompts/topics.yaml", "when": "その話題の資料が検索で当たったときだけ受け取る"},
       {"name": "AI が呼ぶ処理", "path": "prompts/tools.md", "when": "処理を選ぶときに読む"}
     ],
     "placement": [
       {"source": "persona.md", "write": "どの場面でも同じ、話し方と返事の書き方", "dont": "場面で変わる話し方"},
       {"source": "topics.yaml", "write": "その話題にだけ当てはまること", "dont": "どの話題にも当てはまる進め方"}
     ]
   }
   ```

   `placement` は、ファイルごとに何を書き、何を書かないかの決まりです。
   置き場所の違いを探す役が使います。
   無ければ、置き場所の違いの観点は飛ばします。

2. 資料を 1 つにまとめます。

   ```bash
   python3 <このスキルのフォルダ>/scripts/review_prompts.py collect --manifest prompt-sources.json
   ```

   `.prompt-review/sources.md` に、資料と置き場所の決まりが入ります。
   前の回の結果（`findings-*.json`）は消えます。

3. 5 つの観点ごとに 1 つずつ、レビューする役を並べて立てます。
   役には次のとおりに頼みます。

   ```
   あなたは、AI への指示を読み比べるレビュー役です。受け持つ観点は「<観点>」です。
   1. <このスキルのフォルダ>/references/review.md を読む。
   2. .prompt-review/sources.md を最初から最後まで読む。
   3. 「<観点>」に当たるものを全部、review.md の形の JSON の配列で .prompt-review/findings-<観点>.json に書く。
   ほかのファイルは書き換えない。返事には、書いた件数だけを書く。
   ```

4. 5 つとも終わったら、引用を確かめます。

   ```bash
   python3 <このスキルのフォルダ>/scripts/review_prompts.py check
   ```

   資料に無い引用は外れ、引用が足りなくなったものは「外したもの」に移ります。
   結果は `.prompt-review/review.md` に出ます。
   役が挙げたものも AI の見立てなので、本当に食い違うかは、人が全文を読んで決めます。

## テストで外れた会話の直し方

外れた会話を直す目的は、採点に通すことではなく、お手本の会話に近づけることです。
外れるたびに、その場面の文を 1 行足すと、同じ種類の応対が散らばり、ぶつかる決まりが増えます。

最初に、外れた会話をお手本の会話と左右に並べ、誰の外れかを決めます。
ボットがお手本と違う方向に進んだなら、ボットの外れです。
ボットがお手本と同じことを言っているのに落ちたなら、採点の基準か採点役の外れです。
利用者役の AI がお手本と違うことを言って会話がそれたなら、利用者役の外れです。
ボットの指示を直すのは、ボットの外れのときだけです。

ボットの外れなら、会話の記録で、その返事の前に何を検索し、何を読んでいたかを見ます。
正しい資料を読んでいなければ、指示ではなく、検索か資料を直します。
正しい資料を読んだのに違うことを言ったなら、何を見分けられなかったかを 1 文で言い直します。

そのうえで、直す場所を決めます。
決まりのとおりに動いて外れたなら、決まりがお手本と逆なので、逆を言う文を直します。
どの話題にも出る外れなら、共通の指示の文を直します。
その話題だけの外れなら、話題ごとの手順書を直します。
同じ型の応対が、いくつもの話題でばらばらに書かれていたら、1 つの流れとしてまとめ、散らばった文を消します。

文を直すときも、このスキルの「しないこと」はしません。
直したら、外れた問題に加えて、前に通っていた問題も流します。
前に通っていた問題が落ちたら、その直しは特定の会話に合わせたものだったと見て、直し方を考え直します。

決まりが守られないときに、AI の考える量やモデルを上げて直そうとはしません。
上げても直らないことが多く、返事のすべてが遅くなります。
どの指示のどこが守られない原因かを考えて、指示を直します。
