# 実装サブエージェントへの委譲（issue-loop Step 4-6a）

実装は**実装サブエージェントへ委譲する**（会話している本体が直接コードを書かない）。

理由: 調査中に読んだ「捨てた案・使わなかったファイル・外した方針」を引きずると実装がぶれる。実装サブには **plan（4-3.6）＋対象ファイルだけ**を渡し、調査の経緯・Slack・画像などの文脈は渡さない。きれいな文脈で、決まった方針だけに集中させる。

## 指示に必ず入れる項目（欠けたら委譲し直す）

- 承認済みのゴール（plan の Goal）
- やらないこと（範囲を広げさせない）
- 検証の期待値（チェックコマンドが通る／満たすべき挙動）
- 対象ファイルとそれぞれの役割（plan の Scope）
- やり直しのときは「直す指摘」（4-6d で出た不足）
- 同じ根本原因は範囲内で全部直す。無関係な編集はしない

## 新しい UI を足すとき

新しいグラフ・表などを足す前に、**既存の似たコンポーネントを 1〜2 個読んで、その決まりに合わせる**ことを指示に書く。色・体裁・凡例・単位・レイアウトを独自に決めない。リポジトリにグラフや UI の決まりを書いた文書があれば、それを読ませる。

## 実装サブの出力に必ず含めるもの（欠けたら委譲し直す）

- 変更したファイルの一覧
- 実行した検証とその結果
- 残っているリスク・止まっている点
- 承認された範囲を完了したか
